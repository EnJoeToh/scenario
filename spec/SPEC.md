# Scenario v0.1 仕様

## 1. 目的

Scenarioは、独自記法のシナリオテキストをHTMLへ整形するツールである。

主な利用者と利用方法は次の2つとする。

- 執筆者は、任意のテキストエディタで原稿を編集し、ローカルのリアルタイムプレビューで確認する。
- 一般利用者は、公開Webアプリへテキストを入力し、プレビューしたHTMLを保存する。

Node CLIとWebアプリは、同じTypeScript製のパーサー、文書モデル、レンダラーを使用する。

## 2. v0.1の範囲

### 提供する機能

| 機能 | CLI | Web版 |
|---|---|---|
| 縦書きHTML | 対応 | 対応 |
| 横書きHTML | 対応 | 対象外 |
| プレビュー | ファイル保存時に自動更新 | ボタン操作で生成・表示 |
| 自己完結したHTMLの保存 | 対応 | 対応 |
| 新旧2原稿の差分 | 対応 | 縦書きで対応 |
| 差分中間テキストの保存・再描画 | 対応 | UIでは提供しない |
| 通常原稿のテキスト保存 | エディタを使用 | `.txt`のダウンロード |
| 縦書きの字下げ設定 | 設定ファイルで変更 | 組み込みデフォルト固定 |

### 対象外

- DOCX生成
- CLIによるPDF生成
- Git履歴との比較
- Webアプリでの横書き・自動更新プレビュー・字下げ設定変更
- Webアプリでの原稿ファイル読み込み・差分中間ファイルの読み込みと保存
- サーバーへの原稿保存
- アカウント、共同編集
- Webフォントの埋め込み
- マークアップの入れ子

PDFが必要な場合は、保存したHTMLをChromeで開き、ブラウザの印刷機能からPDFとして保存する。

## 3. コマンド

```console
# エディタで保存した原稿をリアルタイムにプレビューする
scenario preview manuscript.txt

# プレビューと同時にHTMLを自動保存する
scenario preview manuscript.txt -o output/manuscript.html

# HTMLを生成する
scenario build manuscript.txt

# 2つの原稿から差分HTMLを生成する
scenario diff old.txt new.txt
```

`preview`の`-o`（`--output`）は任意とし、指定時は起動時と原稿・設定の更新時に自己完結HTMLを保存する。保存HTMLにはプレビュー用スクリプトや警告UIを含めない。相対出力パスは実行ディレクトリを基準とし、原稿と設定ファイルへの上書きは拒否する。更新失敗はプレビューに表示し、その後の原稿・設定変更で再試行する。

フォーマットは`vertical`または`horizontal`を指定できる。

```console
scenario preview manuscript.txt --format vertical
scenario build manuscript.txt --format horizontal
```

縦書きではレイアウト設定ファイルを指定できる。

```console
scenario preview manuscript.txt \
  --format vertical \
  --layout examples/scenario.layout.json
```

設定ファイルの検索順は次の通りとする。

1. `--layout`で明示されたファイル
2. 原稿と同じディレクトリの`scenario.layout.json`
3. 組み込みデフォルト

`diff`では、新原稿のディレクトリを設定ファイルの検索基準にする。

## 4. 入力形式

入力はUTF-8のプレーンテキストとする。改行コードは読み込み時にLFへ正規化する。

### 4.1 構造記法

| 記法 | 意味 |
|---|---|
| `☆ 作品名` | 作品タイトル |
| `★ 第一部` | 部タイトル |
| `■ 100 導入` | 番号付きシーン |
| `■ 導入` | 自動採番シーン |
| `＠ 部屋の中。` | ト書き |
| `太郎「こんにちは」` | 鉤括弧の台詞 |
| `太郎（心の声）` | 丸括弧の台詞 |
| `→三日後` | 行末寄せの通常本文 |
| `＊`だけの行 | 中央揃えの区切り（`×　　×　　×`） |
| その他 | 通常本文 |

構造記号の直後にある空白は取り除く。

```text
→文章
→ 文章
```

上記2行は同じ内容として扱う。行頭に`→`そのものを表示する場合は、`\→`とエスケープする。

### 4.2 シーン判定

全角の`＊`だけの行（前後の空白は許容）は区切りブロックとして扱い、シーンを終了しない。
区切りは`×　　×　　×`（記号間は全角空白2文字）を表示する。
横書きでは左右中央に配置し、前後に本文1行分（1.5em）の空きを設ける。
縦書きでは1列内の上下中央から全角2文字分（2em）上に配置し、前後に1列分の空きを設ける。
隣接する空きは大きい方を採用し、ページの先頭・末尾に空きだけの列は作らない。
字下げ設定は適用しない。半角の`*`やメモ内の`＊`は通常の文字として保持する。

- 行頭の`■`で新しいシーンを開始する。
- シーン番号には整数または`100.1`のようなドット区切りの枝番を使用できる。
- 数字と枝番に一致しない`■`直後の文字列はシーンタイトルとして扱い、番号は自動採番する。
- 次の`■`、`★`、`☆`またはファイル終端で現在のシーンを終了する。
- 空行だけではシーンを終了しない。空行は構造上の区切りとして無視する。
- シーン外の通常本文は保持し、暗黙のシーンは生成しない。
- シーンタイトルは必須とする。タイトルのない`■`は通常本文として扱い、警告する。

### 4.3 シーン番号

- 番号のないシーンには、未使用の正整数をファイル順に付与する。
- 明示された番号と原稿上の順番は変更しない。
- 主番号は表示時に3桁へゼロ埋めする。
- 枝番はそのまま表示する。

```text
1     → 001
100   → 100
100.2 → 100.2
```

HTMLのシーンIDは次の形式とする。

```text
100   → scene-100
100.2 → scene-100-2
```

重複番号は許可するが警告する。2件目以降のIDには出現番号を付ける。

```text
scene-100
scene-100--2
```

重複番号へのリンクは最初のシーンを参照し、曖昧なリンクとして警告する。

## 5. 文章内マークアップ

| 記法 | 意味 |
|---|---|
| `[+ 太字]` | 太字 |
| `[- 削除]` | 取り消し線 |
| `[* 赤字]` | 赤字 |
| `[# 青字]` | 青字 |
| `>> 100` | シーンへのリンク |

装飾マークアップには半角の角括弧`[]`を使用する。`〔〕`形式はサポートしない。シーンリンクは角括弧を使わず、`>> 100`と記述する。装飾記号・リンク記号の直後の空白は省略できる。

マークアップ前後の通常文字列はHTMLエスケープする。入力中の任意のHTMLタグは実行しない。マークアップの入れ子はv0.1ではサポートしない。

## 6. 複数行メモ

複数行メモは、`::: 色名`または`:::色名`で開始し、`:::`で閉じる。色名の前の空白は省略できる。

```text
::: red
ここはあとで修正する。
伏線との整合性も確認する。
:::
```

```text
::: blue
演出上の注意。
小道具を確認する。
:::
```

- 色名は`red`、`blue`、`green`、`orange`、`purple`、`gray`の6種類とする。
- 未知の色名は警告し、開始行・終了行を含めて通常本文として保持する。
- 旧形式の`::: memo 色名`も互換入力として受け付ける。
- メモ内の改行は保持する。
- メモ内でも文章内マークアップとシーンリンクを使用できる。
- メモ同士の入れ子はサポートしない。内側の開始記法はメモ本文として扱い、最初の`:::`で外側も閉じる。未閉鎖メモは末尾まで読み込み、警告する。
- メモは縦書き・横書きとも字下げなしとし、メモ前後へ自動的な空きは追加しない。
- メモは指定色の1px・角丸6pxの枠で囲む。枠は文字配置に影響しない重ね描きとする。
- 縦書きでは文字を本文の上端から1文字分（12pt）下げ、1列18文字までで折り返して下端にも1文字分を確保する。中央揃えにはしない。同じブロック内の各行は共通の上端に揃える。メモ内ではぶら下げず、18文字の範囲に収める禁則処理を行う。ページをまたぐ場合はページごとに枠を描く。本文のシーン枠と他の本文の組版設定は変更しない。
- 行内の赤字・青字にも、装飾に由来する字下げや左右の余白は追加しない。
- メモの背景には指定色を約7%の不透明度で敷く。縦書きではページ内の注記の文字送りに合わせ、背景と枠を文字の上端から3pt上、下端から3pt下までとする。横書きのシーン内では背景と枠を左右の内側余白へ広げてシーン枠まで密着させる。文字位置と改ページ位置は変えない。
- 1ページに収まるメモは可能な限り途中分割しない。

## 7. 行末寄せ

行頭の`→`はその行の論理的な行末寄せを表す。

- 縦書きでは行の下側へ寄せる。
- 横書きでは右へ寄せる。
- 複数行を寄せる場合は各行に`→`を付ける。
- 行内では文章内マークアップを使用できる。

```text
→三日後
→企画・山田
```

文書モデルでは通常本文に`alignment: "end"`を付与して表現する。

## 8. 文書モデル

実装はTypeScriptの判別可能Unionを使用する。以下は主要な型の抜粋であり、完全な定義は`src/model.ts`を参照する。

```ts
type ScenarioNode = Heading | Scene | Block;
type Block = TextBlock | Conversation | MemoBlock | Separator;

interface ChangeInfo { change?: "added" | "deleted" }

interface TextBlock extends ChangeInfo {
  type: "text" | "stage";
  text: RichText;
  alignment: "start" | "end";
  sourceLine: number;
}

interface MemoBlock extends ChangeInfo {
  type: "memo";
  color: "red" | "blue" | "green" | "orange" | "purple" | "gray";
  lines: RichText[];
  sourceLine: number;
}

interface Separator extends ChangeInfo {
  type: "separator";
  sourceLine: number;
}
```

すべてのノードとブロックは、元原稿の行番号を保持する。

## 9. 縦書きレイアウト

### 9.1 ページ

| 項目 | 値 |
|---|---|
| 用紙 | A4横 |
| 寸法 | 297mm × 210mm |
| 組方向 | 縦書き、右から左 |
| 1行 | 20文字 |
| 1ページ | 40行 |
| 本文文字サイズ | 12pt |
| 文字送り | 12pt |
| 行送り | 20pt |
| 組幅 | 約282.2mm |
| 左右余白 | 約7.4mm |
| 組高 | 約84.7mm |
| 上下余白 | 約62.7mm |
| 本文位置 | 上下中央 |
| ページ番号 | 下中央、下端から約8mm |

ページはレンダラーが明示的に分割し、ブラウザの自動改ページだけには依存しない。

```html
<section class="page">
  <main class="page-body">...</main>
  <footer class="page-number">1</footer>
</section>
```

印刷CSSはA4横への配置とページ区切りだけを担当する。

```css
@media print {
  @page {
    size: A4 landscape;
    margin: 0;
  }

  .page {
    break-after: page;
    box-shadow: none;
  }
}
```

### 9.2 シーン表示

縦書きではシーンを細いグレーの直線枠で囲む。

- 枠線は1px、色は`#ccc`、角丸なし
- 背景色なし
- シーンタイトルはゴシック体・太字
- シーンタイトルの先頭へ`○`を付ける
- シーン番号は枠の外の右下に、横書きと同じグレー背景・白文字のラベルを横向きにぶら下げる。主番号は半角数字で3桁ゼロ埋めし、枝番は維持する（`001`、`100.2`など）。
- ページをまたぐシーンはページごとに枠を分割し、各枠へ同じ番号を表示する。前ページの枠は左辺、次ページの枠は右辺を省略し、3ページ以上にまたがる途中の枠は左右の辺を省略する。枠と番号は本文の20字×40行の外側へ配置する。枠の下辺は本文の下端から8ptの位置に固定し、番号用の空間は枠内に確保しない。文字配置と改ページ位置は変更しない
- リンク用IDは維持する
- シーン間は1行空ける

### 9.3 字下げ

デフォルト値は次の通りとする。単位は全角文字数である。

| 要素 | 字下げ |
|---|---:|
| 作品タイトル | 0文字 |
| 部タイトル | 1文字 |
| シーンタイトル | 0文字 |
| ト書き | 2文字 |
| 通常本文 | 0文字 |
| 台詞の先頭行 | 0文字 |
| 台詞の折り返し | 1文字 |

CLIでは設定ファイルにより上記の値を0〜19の整数で変更できる。Web版は上記の組み込みデフォルトを使用し、設定変更UIは提供しない。

保存HTMLには設定を適用した文字配置を埋め込み、外部設定ファイルへ依存しない。

### 9.4 スペーシング

字下げとブロック間の空きは別の概念として扱う。

| 境界 | 空き |
|---|---:|
| 作品タイトルの後 | 0行 |
| 部タイトルの前 | 1行 |
| 部タイトルの後 | 2rem（24pt） |
| シーン間 | 1行 |
| シーンタイトルの前後 | 0行 |
| ト書きの前後 | 0行 |
| 連続するト書きの終了後 | 0行 |
| 台詞の前後 | 0行 |
| 通常本文の前後 | 0行 |
| メモの前後 | 0行 |
| 行末寄せ行の前後 | 0行 |

空行自体には追加スペーシングの意味を持たせない。

### 9.5 書体

作品タイトルは19.2pt（本文の1.6倍）・太字とし、左側に6pxの`#555`の罫線を付ける。部タイトルは14.4pt（本文の1.2倍）・標準ウェイトとする。その他の本文は12ptとする。見出しの字下げは各見出しの文字サイズを基準にする。
見出しは拡大後の文字送りで折り返し、本文と同じ組高に収める。

書体はv0.1ではユーザー設定にしない。

| 要素 | 書体 |
|---|---|
| 作品タイトル | ゴシック |
| 部タイトル | 明朝 |
| シーンタイトル | ゴシック |
| ト書き | ゴシック |
| 話者名 | ゴシック |
| 台詞本文 | 明朝 |
| 通常本文 | 明朝 |
| ページ番号 | ゴシック |

```css
:root {
  --font-mincho: "Yu Mincho", "Hiragino Mincho ProN",
    "Noto Serif JP", serif;
  --font-gothic: "Yu Gothic", "Hiragino Sans",
    "Noto Sans JP", sans-serif;
}
```

フォントファイルはHTMLへ埋め込まない。閲覧環境に先頭のフォントが存在しない場合は、次の候補へフォールバックする。

### 9.6 禁則とぶら下げ

- 句読点・閉じ括弧（`、。，．？！）〕］｝〉》」』】〙〗〟’”»`）は、各行の末尾で最大2文字分まで本文の組高の外へぶら下げる。
- `。」`などの連続記号も上限内でまとめてぶら下げる。上限はその行の文字サイズにおける2文字分とする。
- 小書き仮名など、それ以外の行頭禁則と開き括弧の行末禁則は、手前で折り返して回避する。
- 対象記号が長く連続して上限内に収まらない場合も、手前で折り返す。
- 1ページ40列は維持する。枠と番号の位置はぶら下げ量に関係なく固定し、ぶら下がった文字と番号が重なる場合は許容する。

### 9.7 ページ境界

- シーンタイトルだけをページ末に残さない。
- シーンタイトルと最低1行の内容を同じページへ配置する。
- シーン全体を同一ページへ収める必要はない。
- 話者名と台詞の冒頭は可能な限り同じページへ配置する。
- 収まらないブロックは次ページへ送る。
- 1ページを超えるブロックだけは途中分割を許可する。

## 10. 横書きレイアウト

横書きは連続した閲覧用レイアウトとし、20字×40行の固定グリッドは適用しない。印刷時はA4縦を想定するが、縦書きのような明示的なページ分割やページ番号は生成しない。

### 10.1 基本レイアウト

| 項目 | 値 |
|---|---|
| 組方向 | 横書き、左から右 |
| 画面表示 | 中央寄せの連続レイアウト |
| 本文幅 | 最大170mm |
| 印刷想定 | A4縦 |
| 印刷余白 | 上18mm、左右18mm、下20mm |
| 本文書体 | 明朝 |
| 本文文字サイズ | 12pt |
| 行送り | 1.5 |
| ページ番号 | なし |

```css
@media print {
  @page {
    size: A4 portrait;
    margin: 18mm 18mm 20mm;
  }
}

.horizontal-document {
  width: min(170mm, 100%);
  margin-inline: auto;
  font-family: var(--font-mincho);
  font-size: 12pt;
  line-height: 1.5;
}
```

### 10.2 要素の表示

- シーンは右上だけ角丸を付けない、角丸の枠付きカードとして表示する。
- シーン番号を右上のグレー背景・白文字のラベルで表示する。
- 作品タイトルと部タイトルは20pt・標準ウェイトのゴシック体で表示する。作品タイトルには左罫線を付け、部タイトルはグレー背景・白文字の帯にする。
- シーンタイトルは先頭に`○`を付け、左寄せ、ゴシック体・太字とする。
- 台詞は話者名と本文を分けて表示する。
- 話者名は中央寄せ、ゴシック体とする。話者名の前に`1: 太郎`の形式で台詞番号を表示する。鉤括弧・丸括弧の台詞を対象に、シーンや部をまたいで文書全体で1から連番を振る。ト書き・本文・メモは採番しない。
- 台詞本文は最大120mmのinline-blockとし、ブロック全体を中央へ配置する。本文内部は明朝体・左寄せとする。
- ト書きと通常本文はゴシック体・左寄せとする。
- `→`行は右寄せする。
- メモは指定された色を維持する。

### 10.3 字下げ

| 要素 | 字下げ |
|---|---:|
| 作品タイトル | 0文字 |
| 部タイトル | 0文字 |
| シーンタイトル | 0文字 |
| ト書き | 2文字 |
| 通常本文 | 0文字 |
| 台詞の先頭行 | 0文字 |
| 台詞の折り返し | 1文字 |

台詞本文は1文字分の左余白と、マイナス1文字の先頭行字下げを組み合わせ、折り返し部分だけを1文字下げる。

### 10.4 スペーシング

| 境界 | 空き |
|---|---:|
| 作品タイトルの後 | 8mm |
| 部タイトルの前後 | 8mm |
| シーン間 | 8mm |
| シーンタイトルの後 | 2mm |
| 台詞の後 | 4mm |
| 通常本文の後 | 1mm |
| 連続するト書きの途中 | 0 |
| ト書きの連続終了後 | 1.5em |
| メモの前後 | 0 |

横書き用のレイアウト値はv0.1ではユーザー設定にしない。CLIは組み込みデフォルトを使用する。Web版は横書きを提供しない。

## 11. Webアプリ

### 11.1 画面と操作

- 画面上部の「通常」「差分」ボタンでモードを切り替える。
- 「原稿を編集」と「プレビューを表示」（差分モードでは「差分を表示」）は同じ位置に並べ、表示中の画面を強調する。
- 通常モードでは1つの原稿、差分モードでは旧原稿と新原稿を入力する。新旧の入力欄は広い画面では左右、狭い画面では上下に配置する。
- ボタン操作で組版し、成功すると入力画面から縦書きプレビューへ切り替える。入力中の自動組版は行わない。
- 「原稿を編集」で入力へ戻れる。入力内容は画面・モードの切り替えで保持する。編集すると以前の結果を無効にし、再生成が必要になる。未編集なら結果を再利用する。
- 組版と差分計算はWeb Workerで実行し、計算中も中止・編集・モード変更を受け付ける。編集・モード変更時は進行中の処理を中止する。
- 差分は片方の原稿が空でも計算できる。両方が空の場合と、通常原稿が空の場合は生成しない。
- 縦書き・A4横のプレビューを画面幅に合わせて縮小する。画面の高さに合わせてプレビュー領域を調整し、保存ボタンを下部の右側に配置する。短い画面ではページ全体のスクロールを許容する。
- 通常・差分それぞれの公開用サンプルを挿入できる。入力済みの原稿を置き換える場合は確認する。
- 警告をプレビューに表示する。差分の警告には旧原稿・新原稿の区別を付ける。

### 11.2 保存とプライバシー

- 通常モードでは「原稿を保存」で現在の入力をUTF-8の`.txt`としてダウンロードする。プレビュー生成前・組版エラー時も利用できる。空の入力では保存ボタンを無効にする。
- 通常原稿の保存名は生成前・編集後の再生成前は`scenario.txt`、生成後は作品タイトルを基にする。タイトルなしは`scenario`を使用し、禁止文字を置換してタイトル部分を80文字までに制限する。
- 両モードでプレビューの「HTMLを保存」を提供する。差分モードでは原稿テキスト・差分中間テキストの保存は提供しない。
- 保存HTMLは本文、CSS、ページ分割、ページ番号を含む自己完結形式とし、プレビュー用の縮小CSSを含めない。外部JavaScript・外部CSS・ネットワーク接続は不要とする。
- 原稿はブラウザ内で処理し、外部送信・自動保存は行わない。再読み込み・画面を閉じる操作では入力内容が失われる。
- PDF・DOCXは出力しない。PDFが必要な場合は保存HTMLをブラウザで印刷する。

### 11.3 ビルドと公開

- Viteで`web/`と共有コアを静的アセットへビルドし、`dist/`へ出力する。
- アセット参照は相対パスとし、GitHub Pagesのリポジトリ配下で配信できるようにする。
- `.github/workflows/pages.yml`は`main`へのpushまたは手動実行でテスト・ビルドを行い、`dist/`をGitHub Pagesへ公開する。GitHub側でPagesの公開元をGitHub Actionsに設定する必要がある。
- CLIとWeb開発・ビルドはNode.js 22.18.0以上で実行し、公開Web版はブラウザだけで動作する。ワークフローではNode.js 24を使用する。
- 公開用の`examples/sample.txt`と`examples/diff-before.txt`・`examples/diff-after.txt`を取り込む。`dist/`内のビルド結果だけを配信する。

## 12. 差分HTML

`scenario diff old.txt new.txt`は、編集可能な差分テキストと、通常のシナリオ組版による差分HTMLを生成する。既定は縦書きとし、`--format horizontal`および`--layout`も使用できる。

### 12.1 比較方法

1. 改行コードをLFへ統一し、Myers方式の行diffを中間ファイルへ保存する。
2. 中間ファイルから旧原稿・新原稿を復元し、それぞれ従来のパーサーで解析する。注記の開始・終了記法を差分記法と混在させない。
3. シーン見出し・本文・台詞・注記などのブロック列を比較する。シーン番号は比較キーから外す。
4. 変更範囲内の同種ブロックを順序を保って対応付ける。台詞は同じ話者、注記は同じ色・同じ行数に限る。類似度0.6以上を行内統合の対象とする。見出しが変わったシーン同士も対応付ける。
5. 対応するブロックは装飾・リンクを含む書記素単位で差分を強調する。対応しないブロックは追加・削除として残す。
6. 通常のレンダラーで縦書き・横書きに組版する。

差分内のシーン番号は1から振り直す。変更前の番号の維持は行わない。変更後のシーンへのリンクは振り直したIDへ対応付ける。
ブロックの類似度は隣接文字の重なりを用い、短文は共通文字列による補助判定を行う。対応候補が1万組を超える変更範囲はブロック単位で表示する。行・ブロックdiffの編集距離が2000を超える場合はエラーとする。

### 12.2 中間形式

先頭行は`#!scenario-diff-v1`とし、以降は全行に空白2文字（変更なし）、`- `（削除）、`+ `（追加）を付ける。原稿の行頭記号も含め、接頭辞の後ろの内容は変更しない。通常の原稿ではこの接頭辞を解釈しない。
この形式により`:::red`などの注記、`>> 100`のリンク、差分接頭辞と似た本文も復元できる。空行や末尾改行も接頭辞で保持する。不正なヘッダー・接頭辞はエラーとする。

CLIのHTML出力時は同じ出力名の拡張子を`.txt`へ変えた中間ファイルも保存する。既定は`<新原稿名>.diff.html`と`<新原稿名>.diff.txt`とする。`-o`に`.txt`を指定した場合は中間ファイルだけを保存する。どちらの出力も入力原稿・設定ファイルを上書きしてはならない。
中間ファイルは`build`・`preview`へ渡して再描画できる。ヘッダーで自動判別し、`.diff.txt`という名前の入力には正しいヘッダーを必須とする。

### 12.3 表示

- ブロック単位の追加箇所は緑、削除箇所は赤の付箋型で表示する。縦書きは上端、横書きは左端に4pxの太線を置き、約7%の薄い背景色を添える。行内修正は追加`#a8e9b2`・削除`#f7b4b4`の背景色で強調し、差分の角丸枠は付けない。削除した文字には濃いグレー（`#555`）・2pxの打ち消し線を添える。原稿由来の背景色・取り消し線は維持する。
- 小さな修正はひとつの台詞・本文内へまとめ、大きな変更はブロック単位で表示する。
- 連続する同種のブロック変更は、台詞・ト書き・注記をまたいでひとつの付箋型の範囲にまとめる。変更なし・変更種別の切り替わり・シーンや見出しの境界で分ける。縦書きではページごとに分ける。シーン全体の変更は見出しと本文を同じ範囲に含める。
- 注記の色・装飾・文字位置は維持し、注記全体の追加削除には外側の線を添える。
- シーン枠・固定グリッド・禁則・ページ番号など、通常の組版を使用する。
- 全文を表示し、変更のない範囲も省略しない。凡例とシーン番号の振り直しを表示する。
- 出力は自己完結したHTMLとする。

この方式ではシーンの移動を特別に検出しない。移動は旧位置での削除と新位置での追加として表示する。
ブロック対応は推定であり、繰り返しや似た文が多い原稿では意図と異なる対応になる場合がある。

GitリポジトリやGit履歴には依存しない。

### 12.4 従来の左右比較

`--comparison`を指定すると従来の行単位・左右比較HTMLを生成し、中間ファイルは保存しない。このモードのみ`--context`（既定3）を使用できる。`--format`・`--layout`は使用しない。

## 13. 警告

少なくとも次の状態を警告として報告する。

- シーン番号の重複
- 重複シーン番号への曖昧なリンク
- 存在しないシーン番号へのリンク
- タイトルのない`■`
- 閉じられていないメモブロック
- 未知のメモ色
- 範囲外のレイアウト設定値

警告は処理を停止させず、CLIとWeb UIの両方で利用者へ表示する。レイアウト設定の警告は設定変更を提供するCLIのみが対象となる。

## 14. 実装方針

- TypeScriptで新規実装する。
- Node CLIとWebアプリでコア実装を共有する。
- HTMLへ出力する前に必ず構造化された文書モデルを生成する。
- 入力と期待する文書モデルをJSON fixtureとして管理する。
- 縦書きのページ組版は固定グリッドとしてテストする。
