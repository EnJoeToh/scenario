# Scenario

独自記法のシナリオ原稿から、縦書き・横書きHTMLと差分HTMLを生成します。
CLIと縦書き専用のWeb版を提供します。開発・CLI実行にはNode.js **22.18.0以上**が必要です。CLIは外部パッケージ・ビルド不要で動作し、Web版の開発・配信用ビルドにはViteを使用します。公開済みのWeb版はブラウザだけで利用できます。

## 使い方

### Web版（縦書き）

「通常」「差分」を選び、入力画面へ原稿を貼り付けます。「プレビューを表示」または「差分を表示」を押すと、縦書きのプレビュー画面へ切り替わります。「原稿を編集」で入力画面へ戻れます。原稿は画面・モードを切り替えても保持し、編集後はボタンを押して再生成します。

編集とプレビューのボタンは画面上部の同じ位置に並べ、表示中の画面を強調します。入力を変更していなければ、再計算せずにプレビューへ戻れます。保存ボタンは画面右下に配置しています。

通常モードでは「原稿を保存」で入力中のテキストをUTF-8の`.txt`ファイルとして保存できます。入力画面・プレビュー画面のどちらからも保存でき、プレビュー生成前や組版エラー時にも使用できます。生成前と編集後の再生成前は`scenario.txt`、生成後は作品タイトルをファイル名に使用します。タイトルがなければ`scenario.txt`とし、ファイル名に使えない記号は置換します。

差分モードは旧原稿と新原稿を左右に並べ、スマートフォンでは上下に配置します。片方を空にして全文の追加・削除を表示することもできます。両モードとも、プレビュー画面の「HTMLを保存」で単体HTMLを保存できます。差分モードではHTMLのみ保存します。

組版と差分計算はWeb Workerで実行し、計算中に中止・編集・モード変更ができます。プレビューは画面幅に合わせて縮小し、保存HTMLはCLIと同じ組版・元のA4横の寸法を保ちます。

原稿はブラウザ内で処理し、外部送信・自動保存は行いません。画面を閉じる前に原稿を手元に保存してください。レイアウト設定の変更はCLIを使用します。

```sh
npm ci
npm run web:dev
```

表示されたローカルURLを開いてください。Web版の開発・ビルドには開発用依存関係が必要です。CLIは従来どおり外部パッケージなしで実行できます。

```sh
# 配信用の静的ファイルをdist/へ生成
npm run web:build

# ビルド結果をローカルで確認
npm run web:preview
```

#### GitHub Pagesへの公開

1. このリポジトリをGitHubへpushします。
2. GitHubのリポジトリ設定で **Settings → Pages → Build and deployment → Source → GitHub Actions** を選択します。
3. `main`へpushすると、`.github/workflows/pages.yml`がテスト・ビルド・公開を実行します。設定前にpushした場合は、Actions画面の「Publish Web app to GitHub Pages」から「Run workflow」を実行してください。
4. 公開URLはワークフローの`github-pages`環境とSettings → Pagesで確認できます。通常は`https://<ユーザー名>.github.io/<リポジトリ名>/`です。

公開するのは`dist/`内のWebアプリだけです。CLIの出力フォルダは配信対象に含めません。ビルド時には公開用の`examples/sample.txt`と`examples/diff-before.txt`・`examples/diff-after.txt`をサンプルとして取り込みます。`dist/`はGit管理から除外しています。

### CLI

このフォルダで実行します。

```sh
# 縦書きHTML（省略時の形式）
npm run scenario -- build examples/sample.txt -o output/sample.vertical.html

# 横書きHTML
npm run scenario -- build examples/sample.txt --format horizontal -o output/sample.horizontal.html

# 原稿を保存するとブラウザを自動更新
npm run scenario -- preview examples/sample.txt

# プレビューしながらHTMLも自動保存
npm run scenario -- preview examples/sample.txt -o output/sample.html

# 差分HTMLと編集可能な中間ファイル
npm run scenario -- diff old.txt new.txt -o output/changes.html

# 中間ファイルから横書きHTMLを生成
npm run scenario -- build output/changes.txt --format horizontal -o output/changes.horizontal.html

# ヘルプ
npm run scenario -- --help
```

`node bin/scenario.js …`でも実行できます。`preview`が表示するURLをブラウザで開いてください。
プレビューは`127.0.0.1`でのみ待ち受け、既定ポートは3000です。`--port 3001`で変更できます。
原稿と設定ファイルを200ms間隔で確認し、変更後100msの待機を経て再生成します。
エディタがファイルを置き換えて保存する場合、削除後に再作成する場合にも追従します。
生成・保存エラー時は最後に成功したプレビューとエラーを表示し、その後の原稿・設定の保存で再試行します。
`preview -o 出力.html`は起動時と原稿・設定更新時に、プレビュー用スクリプトを含まないHTMLを保存します。
`-o`を省略するとプレビューのみです。相対パスはコマンドを実行したフォルダを基準にします。
別フォルダからは`node /path/to/scenario/bin/scenario.js preview 原稿.txt -o 出力.html`で実行できます。`/path/to/scenario`は、このツールを配置したフォルダへ置き換えてください。

`build`の出力先を省略すると原稿と同じ場所の`<原稿名>.html`、
`diff`は新原稿と同じ場所の`<新原稿名>.diff.html`と`<新原稿名>.diff.txt`へ保存します。
既存の出力HTMLは上書きします。入力原稿と同じパスへの出力は拒否します。
警告は標準エラー出力へ表示し、処理を続けます。読み書き失敗・引数エラーは終了コード1です。

保存HTMLはCSS・ページ・ページ番号を内包し、JavaScriptやネットワーク接続を必要としません。
PDFは保存HTMLをChromeで開き、ブラウザの印刷機能から保存します。
実際の印刷結果については、ブラウザのヘッダー・フッターを無効にして確認してください。

横書きは左罫線の作品タイトル、グレーのパート帯、
右上の番号ラベル付き角丸シーン枠、中央にまとまる台詞を採用しています。
横書きの話者名には`1: 太郎`の形式で、文書全体の台詞の通し番号を表示します。

## 原稿の差分

`diff`は通常のシナリオと同じ組版で差分を表示します。似た台詞・本文の修正は1行にまとめて、変更箇所だけを緑（追加）・赤（削除）の少し濃い背景色で強調します。大きな書き換えや行・シーンの追加削除は、薄い背景と行頭の4pxの太線による付箋型で示します。縦書きは上端の横線、横書きは左端の縦線です。削除した文字には濃いグレー・2pxの打ち消し線を付けます。`:::red`などの注記は角丸枠で区別し、文章内の装飾、シーン枠と改ページは維持します。

シーン番号は差分内で1から振り直します。番号だけの変更は描画上の変更として扱いません。似たブロックの対応付けは自動判定のため、意図と異なる組み合わせになる場合があります。シーン移動は追加・削除として扱います。

同じ種類の追加・削除が続く箇所は、台詞・ト書き・注記をまたいでひとつの付箋型の範囲にまとめます。変更のないブロック、追加と削除の切り替わり、シーン境界で区切ります。縦書きでページをまたぐ場合はページごとに表示します。行内修正の強い背景色は維持します。

中間ファイルは先頭行が`#!scenario-diff-v1`で、各原稿行の先頭に空白2文字（変更なし）、`- `（削除）、`+ `（追加）を付けたテキストです。注記などの元の記法はそのまま残ります。中間ファイルを編集して`build`や`preview`へ渡せます。誤字修正も旧行と新行を残し、描画時に行内差分へまとめます。

```text
#!scenario-diff-v1
  ■ 宿屋
- 太郎「明日、出発つする」
+ 太郎「明日、出発する」
  :::red
  出発時刻を確認。
  :::
```

`-o output/changes.html`では`output/changes.txt`も生成します。`-o output/changes.diff.txt`とすれば中間ファイルだけを保存します。この例の`output/`内のファイルはGit管理から除外します。

```sh
# 同梱サンプルで差分を確認
npm run scenario -- diff examples/diff-before.txt examples/diff-after.txt -o output/changes.html

# 従来の左右比較も利用可能
npm run scenario -- diff old.txt new.txt --comparison --context 3 -o output/comparison.html
```

通常の差分表示では全文を組版します。`--context`は`--comparison`専用です。

`examples/diff-before.txt`と`examples/diff-after.txt`には、シーン名変更、誤字・一語修正、装飾付き本文、注記内の修正、注記の追加・削除・色変更、シーン全体の追加・削除、番号だけの変更、区切りとリンクの確認例を収録しています。パート名が確認項目に対応しています。

## 区切り

全角の`＊`だけを書いた行は、`×　　×　　×`の区切りとして中央に表示します。
前後に1行分の空きを入れます。縦書きでは1列内の上下中央から全角2文字分（2em）上に配置し、前後に1列ずつ空けます。
ページの先頭・末尾には空きだけの列を作りません。行の前後の空白は許容し、メモ内の`＊`はそのまま表示します。

```text
区切りの前の本文。
＊
区切りの後の本文。
```

## 色付きブロック

`::: 色名`または`:::色名`で開始し、`:::`で閉じます。色名の前の空白は省略できます。

```text
::: blue
演出上の注意。
複数行のメモを書けます。
:::
```

色は`red`・`blue`・`green`・`orange`・`purple`・`gray`の6種類です。
メモは縦書き・横書きとも字下げなしで、指定色の1px・角丸6pxの枠を重ねて表示します。文字位置は変えません。縦書きのメモは上を1文字分（12pt）空け、1列18文字までで折り返して下にも1文字分を確保します。中央揃えにはしません。メモ内ではぶら下げをせず、18文字の範囲で禁則処理します。本文のシーン枠は動かしません。行内の赤字・青字にも左右の余白を追加しません。
背景には指定色を約7%の濃さで薄く敷きます。縦書きでは背景と枠を文字の上下3ptの範囲に寄せ、横書きではシーン外枠の左右端まで広げます。文字位置は変えません。
中の改行を保持し、文章内マークアップとシーンリンクも使えます。
旧形式の`::: memo blue`も読み込めます。

## 縦書きの設定

CLIでは原稿と同じフォルダの`scenario.layout.json`を自動で読み込みます。`diff`では新原稿のフォルダを基準にします。Web版は組み込みデフォルトを使用し、設定ファイルの読み込み・設定変更UIはありません。
`--layout path/to/settings.json`があればそちらを優先します。
指定のない値には次のデフォルトを使用します。各値は0〜19の整数です。

```json
{
  "title": 0,
  "part": 1,
  "scene": 0,
  "stage": 2,
  "text": 0,
  "dialogueFirst": 0,
  "dialogueContinuation": 1
}
```

順に作品タイトル、部タイトル、シーンタイトル、ト書き、通常本文、台詞先頭、台詞折り返しの字下げです。
範囲外の値や壊れたJSONは警告し、デフォルトへ戻します。明示指定したファイルが読めない場合はエラーです。
横書きではこの設定を使用しません。

## v0.1の実装上の判断

- 入力記法は[仕様書](spec/SPEC.md)を参照してください。
- 装飾記号の直後の空白は省略できます。`[*赤字]`と`[* 赤字]`は同じように扱います。
- 明示番号を原稿全体から予約してから、自動番号に未使用の正整数を割り当てます。
- 主番号の先頭のゼロは正規化します。`001`と`1`は同じシーン番号です。枝番の表記は保持します。
- シーン外の本文は原稿の順序で配置します。暗黙のシーンは作りません。
- 台詞は、行全体が`話者「本文」`または`話者（本文）`の形の場合に認識します。括弧が対応しない行は本文として保持します。
- 未閉鎖メモはファイル末尾までをメモとし、警告します。未知の色のブロックは開始行・終了行も含めて通常本文として保持します。
- 縦書きのシーンは細いグレーの直線枠で囲み、枠の外の右下に、横書きのグレー背景・白文字のシーン番号ラベル（`001`など）をぶら下げます。枠の下辺は本文の下端から8ptの位置とし、番号用の空間は枠内に取りません。ページをまたぐシーンは各ページに枠と同じ番号を表示し、前ページは左辺、次ページは右辺を開けます。途中のページは左右とも開けます。
- 縦書きの作品タイトルは19.2pt・太字・左罫線付き、部タイトルは14.4pt・標準ウェイト、本文は12ptです。タイトルは字下げなし、部タイトルは1文字下げをデフォルトにし、作品タイトルの後ろには余白を設けず、部タイトルの前に1行、後ろに2remの余白を設けます。見出しの字下げは各見出しの文字サイズを基準にします。見出しは文字サイズに応じて折り返します。極端な字下げでは、少なくとも1文字が入る位置に字下げを制限します。
- 縦書きは書記素単位で折り返します。ASCIIと半角カナを0.5マス、その他を1マスとして計算し、1列20マス・1ページ40列に分割します。
- 縦書きの句読点・閉じ括弧は行末で最大2文字分までぶら下げます。`。」`などの連続も対象です。小書き仮名などの行頭禁則、開き括弧の行末禁則は手前で折り返します。対象記号が長く連続して上限を超える場合も、手前で折り返します。枠と番号の位置はぶら下げ量に関係なく固定し、ぶら下がった文字と番号が重なる場合は許容します。
- ページ頭と末尾にスペーシングだけの空列は作りません。隣接する前後スペーシングは大きい方を採用します。
- シーン見出しと最初のブロックを一緒に配置します。合計が40列を超える場合は分割し、見出しだけをページ末に残さないことを優先します。
- 差分の中間ファイルはMyers方式の行比較で生成します。描画時は文書構造と類似度で変更ブロックを対応付け、書記素単位で変更を強調します。編集距離が2000を超える比較はメモリ保護のためエラーにします。変更ブロックの対応候補が1万組を超える場合は、行内への統合を省略してブロック単位で表示します。

文字幅の計算は固定グリッド用の近似です。フォントは環境依存なので、英数字の実際の送り幅、
絵文字、複雑な禁則、ブラウザ間の表示・印刷の完全一致は保証しません。
縦書きの見た目とChromeの印刷結果は、実ブラウザでの追加確認が必要です。
Web版は通常原稿と新旧差分の縦書きプレビュー・HTML保存と、通常モードの原稿テキスト保存に対応しています。

## 検証

```sh
npm test
npm run web:build
```

文書モデルのJSON fixture、警告、HTMLエスケープ、固定グリッド、ページ境界、
Myers差分、CLI出力、ファイル監視、プレビューHTTP/SSE、Web用組版処理とCLIの出力一致、空の新旧原稿、差分警告の原稿識別を検証します。
`web:build`は画面・Web Workerを`dist/`へビルドします。画面操作・レスポンシブ表示・ダウンロード・印刷の実ブラウザ確認は自動テストの対象外です。GitHub Pages上での公開動作も別途確認が必要です。
ローカルポートの待ち受けを環境が`EPERM`で拒否する場合、HTTP/SSEテストは理由を表示してスキップします。

## 構成

- `src/model.ts`: 文書モデル・レイアウト設定
- `src/parser.ts`: 記法解析・番号解決・警告
- `src/render.ts`: 横書き描画・縦書き組版・HTML生成
- `src/diff.ts`: 行diff・行内diff・差分HTML
- `src/revision.ts`: 差分中間形式・ブロック対応付け・通常組版用の差分文書
- `src/cli.ts`: コマンド・入出力・プレビュー
- `web/index.html`・`web/style.css`: 通常／差分の入力・プレビュー画面
- `web/main.ts`: モード・画面切り替え、Worker制御、原稿・HTMLの保存
- `web/compile.ts`・`web/worker.ts`: 共通コアによるWeb用組版処理とWorkerの入口
- `vite.config.ts`: Webビルド・相対アセットパスの設定
- `.github/workflows/pages.yml`: テスト・ビルド・GitHub Pagesへの公開
- `test/`: コア・CLI・ファイル監視・Web用組版処理の検証

パーサー、文書モデル、レンダラー、差分処理はNode固有APIに依存せず、CLIとWeb版で共有しています。

## リポジトリに含めるファイル

`examples/`内の原稿・設定サンプル、ソースコード、ドキュメント、Web版の依存関係を再現する`package-lock.json`を含めます。
共通の`.gitignore`では、`output/`・`dist/`・`node_modules/`・ルート直下の生成HTML・環境設定ファイルなどを除外します。
`examples/scenario.layout.json`は公開する設定例として含めます。通常サンプルと差分サンプルをCLIで組版する際に自動で読み込まれます。
